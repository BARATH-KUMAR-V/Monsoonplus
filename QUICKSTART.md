# monsoonplus — quickstart

The one-page version. Full detail is in [`README.md`](README.md).

---

## Just show me the site (2 minutes, no accounts, no keys)

```bash
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173>. That is the complete 7-page application in **Dataset
mode**, reading committed model output. No API key, no backend, no network except map
tiles.

---

## Retrain the model (optional)

```bash
python -m venv .venv
source .venv/Scripts/activate          # Windows Git Bash
# .venv\Scripts\Activate.ps1           # Windows PowerShell
# source .venv/bin/activate            # macOS / Linux

pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

python -m ml.training.train            # ~13 min on CPU, all 4 phases
python -m ml.export.export_predictions # writes frontend/public/data/*.json
```

Or open `notebooks/monsoonplus_colab_training.ipynb` on Colab's free GPU (~10 min) and
download the four JSON files it produces.

## Verify everything

```bash
python -m pytest -q                    # 75 tests
python -m config.segments              # network config self-check
python -m ml.export.check_palette      # WCAG contrast + colourblind check
python -m ml.training.linear_probe     # modality ablation, NumPy only, <1 s
cd frontend && npm run smoke           # 40 data-integrity checks
```

Without `torch_geometric` installed, run the model on the pure-PyTorch twin layers:
`load_checkpoint("ml/checkpoints/monsoonplus_final.pt", graph_layer="dense_gcn")`. See
[`ml/README.md`](ml/README.md).

## Turn on live data (optional)

1. Free key from <https://developer.tomtom.com> (no credit card).
2. `cp .env.example .env`, then put the key on the `TOMTOM_API_KEY=` line.
3. Two terminals:

```bash
python -m collector.collect            # polls TomTom + Open-Meteo
uvicorn backend.app:app --port 8000    # serves Live mode
```

4. Click **Live** in the top bar.

Open-Meteo needs no key at all. Without a TomTom key the collector still records weather
and model predictions, and marks traffic `not_configured`.

## The three modes

| Mode | Reads | Needs |
| --- | --- | --- |
| **Dataset** (default) | committed JSON | nothing |
| **Live** | TomTom + Open-Meteo via the local collector | optional TomTom key |
| **Log** | collected predicted-vs-actual files | the collector, run over time |

Live and Log both fall back visibly rather than failing. The badge in the top bar always
says which one you are actually looking at.

## The one thing to remember for your viva

The Chennai numbers come from a **synthetic** window generated by an explicit physical
process — not measured Chennai traffic. The METR-LA numbers are real, and there the
model is only marginally better than persistence and actually *loses* to the LSTM
baseline. Both facts are displayed on the site itself, in Model Lab. Say it the same way
and the work holds up.

What is genuinely demonstrated: a learned gate whose weights are readable from outside,
which measurably shifts from 54.3% to 67.0% weight on weather+satellite as conditions go
from clear to heavy rain.
